4. IMPLEMENTED ARCHITECTURE AND HOW THE PROJECT WORKS
Next.js Server Components load public content. Client components handle interactive forms, theme switching, galleries, maps and editor interactions. Server Actions perform validated mutations. Public and admin rendering are separated by route groups and authorization boundaries.
Last inspected package versions: Next 16.4.2, React 19.3.0, TypeScript ^5, Tailwind 4.3.3, Supabase JS 2.118.0, Supabase SSR 0.12.7, React Hook Form 7.90.0, Zod 4.6.7, Leaflet 1.9.4, react-leaflet 5.0.0, leaflet.markercluster 1.5.3, Playwright 1.64.1, Prettier 3.9.10. Check package.json/lockfile for future changes.

Public routes
Home renders published home page_sections. /tours supports search/filter/sort. /tours/[slug] loads the requested tour with related itinerary, route, places and media. /destinations and /destinations/[slug] show places. /places is a compatibility route. /map shows the route explorer. /blog and /blog/[slug] show stories. About, FAQ, reviews, contact and legal pages use published page records and generic /[slug] rendering. Sitemap/robots/SEO metadata support discovery. /api/keep-alive makes a minimal anonymous database read.
Visitor flow: home/navigation -> tour/destination discovery -> details/itinerary/photos -> route/map -> inquiry, with tour context carried into the form. No checkout.

Admin routes and workflows
/admin/login is the public login entry. Protected admin includes dashboard, settings, navigation, footer, media, tours, places, reviews, inquiries, team, vehicles, FAQs, blog and pages. Verify current route files for exact naming.
Settings control business identity, contact details, currency, default SEO, colors, curated fonts, radius, trust fields, feature switches and public UI/form labels. Navigation/footer changes are staged and saved transactionally. Media uploads supply reusable records. Tour editors manage itinerary, galleries and route stops. Places can be shared by multiple tours. Reviews require approval and publication. Inquiry statuses and notes are private; changing status does not automatically email the visitor. Generic editors manage remaining content and typed page sections.
Saving published content changes live data rather than maintaining a separate review/draft revision. Successful writes invalidate public cache. Slug changes may break old links; a general redirect manager is future work. Concurrent edits use optimistic timestamps where implemented; reload/reconcile stale conflicts.

Data model
site_settings: editable JSON configuration; canonical slug site-config. navigation-ui and footer settings carry additional editable UI/text. Preserve legacy rows; do not use them as competing public truth.
nav_items: ordered navigation, one child level, visibility/new-tab/link data.
footer_links: ordered grouped links.
pages: route metadata and publication.
page_sections: ordered typed JSON content and visibility tied to parent page.
media: Storage path, MIME/type, dimensions, alt text, caption/credits and mock provenance.
tours: title/slug/descriptions/duration/from-price/currency/difficulty/seasons/tags/transport/gallery/SEO/publication.
itinerary_days: ordered daily title/description/locations/travel time/photos.
places: description, region, tips, best time, photos and coordinates.
route_stops: ordered tour/day/place connection and route coordinate/display data.
vehicles, team_members: editable business presentation.
reviews: guest display/country/rating/date/tour/photo/source, approved/pending and publication.
blog_posts: editorial stories/media/SEO.
faqs: questions and answers.
inquiries: private trip/contact requests, selected tour, status new/replied/booked and internal notes.
admin_users: private Auth user-ID allow-list, constrained to one administrator.
Private support tables/functions handle submission rate limits, older submission-window records and mock media cleanup. Inspect migrations for exact names rather than exposing them publicly.
Editorial data uses slugs, sorting, timestamps, publication and placeholder flags as appropriate. Private inquiries/admin membership deliberately do not behave as public editorial content.

Database policies
RLS is required. Public reads require published content and published parents; reviews also need approval. An itinerary day referenced by a route stop must belong to the same tour. private.is_admin() stays in a non-exposed schema with no arbitrary-user lookup. Membership comes from verified Auth user ID, never user-editable metadata/email alone.
Anonymous and non-admin inquiry/review insert access is denied, including direct Data API/privileged RPC access. Earlier public insert policies were superseded. Admin writes use the owner session with publishable-key clients and RLS. Do not use the privileged submission client for general admin CRUD/public reads.
Migrations are immutable once applied. Add new files under supabase/migrations, and reconcile local versions with the connected remote ledger. Do not apply destructive fixture SQL to the owner-populated project. supabase/seed.sql is starter/draft data; do not overwrite owner content. supabase/admin-bootstrap.sql is for the owner-created Auth user.

Authentication
Next.js 16 uses src/proxy.ts for refresh/protection. Every admin data boundary/action must independently call requireAdmin(); layout/proxy alone is insufficient. Verified Auth user plus admin_users membership is required. Unauthorized sessions are cleared/redirected with correct cookies and private/no-store headers. Logout is POST, uses Supabase signOut and clears local session cookies. Login errors remain generic. Public signup should stay disabled. Admin is noindex and disallowed in robots, but those do not provide security.
Login throttle is per-process: 10 attempts per 10 minutes per identity, bounded to 10,000 tracked entries; it does not replace platform/Auth limits. Keep Server Action origin protection and development argument logging disabled so credentials are not logged.

Submission security
Only src/lib/supabase/submissions.ts may create a SUPABASE_SECRET_KEY client; it imports server-only. It handles verified inquiries/reviews, signed form tickets and private rate limiting. Never expose/log/commit/reuse the secret elsewhere.
Browser obtains signed ticket, waits minimum time, completes Turnstile and submits validated data. Server verifies ticket signature/time, challenge token/action/hostname and Zod payload. Ticket minimum is 1,500ms; maximum age 24 hours. Honeypot produces a success-shaped response without saving. Missing required configuration fails closed.
Production IP identity uses the Vercel-controlled forwarding header, not arbitrary visitor-supplied headers. Identifiers are HMAC-hashed. Transactional database limits are 6 submissions per IP per kind per hour and 3 inquiries per email per hour; expired buckets are removed. Overall 1,000 threshold and each following 100 emit warnings rather than blocking every visitor.
Saved inquiries start new with no visitor-supplied private notes. Submitted public reviews start pending; feature setting defaults off. Consent is required. Optional Resend/Postmark notification runs after saved inquiry; missing provider config skips silently. Last inspected notification helper did not inspect provider HTTP success; real delivery and observability remain follow-up work.

Public reads and errors
Cookie-free publishable client; 60-second tagged Next.js cache. Admin mutations invalidate public-content. Detail queries scope to requested records instead of loading the full catalogue. Database failures must throw sanitized server-logged errors into retry boundaries. Only successful missing-row results lead to not-found. Do not restore old blanket no-store public behavior or silently turn database failures into empty arrays.

Media
Public site-media bucket is intentional; never put private documents/secrets/inquiry attachments there. Public can read; only admin may write. Supported JPEG/PNG/WebP/MP4/WebM. Client rejects over 50 MiB; scales images to at most 2,400px longest edge and compresses at quality 0.82. Video is uploaded, not transcoded. Use meaningful alt text and photo-license credits in captions. Images are stored in Supabase, not hotlinked. Logo/favicon accept appropriate project Storage image URLs. Storage policies and database policies are separate. Back up both objects and database metadata.

Maps and shared places
Overview shows clustered place markers without every route. Choosing a tour shows its numbered stops and line only, fits bounds and supports day highlighting. Selection is shareable with ?tour=slug&day=2. Mobile has compact selectors/detail sheet; desktop has route panel. Tour detail is locked to its own tour.
Repeated/nearby stops are grouped; clustering/spiderfy reduces overlap. Route lines join ordered coordinates; geographic distances are approximate, not authoritative road routing. Owner travel-time values and approximations require verification.
Create/save a place, then connect to one/several/all eligible tours and a day per tour. Reorder in the tour editor. Bulk connection limits: 100 tours per request; RPC caps 500 stops per tour. Existing place/tour connections are skipped in bulk operation; deliberate repeated visits remain editable in tour editor.
Deleting a stop affects that tour. Deleting a place cascades associated stops while keeping tours and itinerary days. Remaining ordered stops reconnect and renumber. Moving place coordinates propagates to connected stops and changes affected tour timestamps to protect stale editors.

Themes and sections
Database CSS variables control surface/text/muted/border/accent/buttons/overlays/status/font/radius. Current design direction is sapphire plus sunset accents, not the older teal. First visit follows device theme; subsequent light/dark choice persists; pre-paint script avoids flash. System is not a third visible toggle option. Respect reduced motion, contrast and keyboard focus.
Supported section types observed: hero, rich_text, gallery, cta, search_bar, stats, how_it_works, destinations, featured_tours, why_us, guide_story, map_preview, reviews, faq, call_to_action. Content is validated by type; collections use published entities. Section count limit 100 with duplicate-ID rejection.
Latest mobile styling still needs a fresh visual production pass; successful compilation alone does not establish design quality.

    contact = group("contact"),

    theme = group("theme");

export function safeLink(value: string): boolean {
  if (!value || /[\s\\\u0000-\u001f\u007f]/.test(value)) return false;
  if (/%(?:0[0-9a-f]|1[0-9a-f]|7f|5c)/i.test(value)) return false;
  if (value.startsWith("/") && !value.startsWith("//") && !/^\/%2f/i.test(value)) return true;
  if (/^#[A-Za-z0-9_-]+$/.test(value)) return true;
  if (/^mailto:[^@?]+@[^@?]+\.[^@?]+$/.test(value)) return true;
  if (/^tel:\+?[0-9()-]+$/.test(value)) return true;
  try {
    const url = new URL(value);
    return url.protocol === "https:" && !!url.hostname && !url.username && !url.password;
  } catch {
    return false;
  }
}

export const readPublished = cache(
  async <K extends ContentTable>(table: K, filter?: Filter): Promise<ContentRows[K][]> => {
    if (!(await getPublicSettings())) return [];
    if (filter && Array.isArray(filter.value) && !filter.value.length) return [];
    return cachedPublic(table + ":" + JSON.stringify(filter ?? null), () =>
      publicRead(table, async () => {
        const client = createPublicClient(),
          rows: ContentRows[K][] = [];
        for (let offset = 0; ; offset += 1000) {
          let query = client
            .from(table)
            .select(columns[table])
            .eq("published", true)
            .order("sort_order")
            .order("id");
          if (filter)
            query = Array.isArray(filter.value)
              ? query.in(filter.column, filter.value)
              : query.eq(filter.column, filter.value);
          if (table === "reviews") query = query.eq("status", "approved");
          if (table === "blog_posts")
            query = query.or("published_at.is.null,published_at.lte." + new Date().toISOString());
          const { data, error } = await query.range(offset, offset + 999);
          if (error) dataFailure(table, error);
          for (const row of data ?? []) {
            const parsed = contentSchemas[table].safeParse(row);
            if (!parsed.success) dataFailure(table + ".validation");
            rows.push(parsed.data as ContentRows[K]);
          }
          if (!data || data.length < 1000) break;
        }
        return rows;
      }),
    );
  },

function visibleCatalogue(catalogue: Catalogue): Catalogue {
  const tourIds = new Set(catalogue.tours.map((t) => t.id)),
    placeIds = new Set(catalogue.places.map((p) => p.id));
  const days = catalogue.days.filter((d) => tourIds.has(d.tour_id));
  return {
    ...catalogue,
    days,
    stops: catalogue.stops.filter(
      (s) =>
        tourIds.has(s.tour_id) &&
        placeIds.has(s.place_id) &&
        days.some((d) => d.id === s.itinerary_day_id && d.tour_id === s.tour_id),
    ),
  };
}
export const getCatalogue = cache(async (): Promise<Catalogue> => {
  const [tours, places, days, stops, media] = await Promise.all([
    readPublished("tours"),
    readPublished("places"),
    readPublished("itinerary_days"),
    readPublished("route_stops"),
    readPublished("media"),
  ]);
  return visibleCatalogue({ tours, places, days, stops, media });
});
export const getTourDetail = cache(async (slug: string) => {
  const tour = await getTour(slug);
  if (!tour) return null;
  const filter = { column: "tour_id" as const, value: tour.id };
  const [days, stops, reviews, faqs] = await Promise.all([
    readPublished("itinerary_days", filter),
    readPublished("route_stops", filter),
    readPublished("reviews", filter),
    readPublished("faqs", filter),
  ]);
  const places = await readPublished("places", {
    column: "id",
    value: [...new Set(stops.map((s) => s.place_id))].sort(),
  });
  const media = await getMedia([

    ...reviews.map((r) => r.photo_media_id),
  ]);
  return {
    catalogue: visibleCatalogue({ tours: [tour], places, days, stops, media }),
    reviews,
    faqs,
  };
});

export function tourRegions(tour: Tour, catalogue: Catalogue) {
  return [
    ...new Set([
      ...tour.regions,
      ...catalogue.stops
        .filter((s) => s.tour_id === tour.id)
        .map((s) => catalogue.places.find((p) => p.id === s.place_id)?.region ?? ""),
    ]),

export function filterTours(catalogue: Catalogue, filters: Filters) {
  const matches = catalogue.tours.filter((t) => {
    const search = (filters.q ?? "").trim().toLowerCase();
    const placeIds = new Set(
      catalogue.stops.filter((s) => s.tour_id === t.id).map((s) => s.place_id),
    );
    const destinations = catalogue.places
      .filter((p) => placeIds.has(p.id))
      .map((p) => p.name)
      .join(" ");
    return (
      (!search ||
        `${t.title} ${t.summary} ${t.tags.join(" ")} ${destinations}`
          .toLowerCase()
          .includes(search)) &&
      (!filters.duration || t.duration_days === Number(filters.duration)) &&
      (!filters.tag || t.tags.includes(filters.tag)) &&
      (!filters.region || tourRegions(t, catalogue).includes(filters.region)) &&
      (!filters.month || t.best_months.includes(filters.month))
    );
  });
  const direction = filters.sort === "price-desc" ? -1 : 1;
  if (filters.sort === "price-asc" || filters.sort === "price-desc")
    matches.sort((a, b) => {
      if (a.price_from == null) return b.price_from == null ? 0 : 1;
      if (b.price_from == null) return -1;
      return a.currency.localeCompare(b.currency) || direction * (a.price_from - b.price_from);
    });
  if (filters.sort === "duration-asc") matches.sort((a, b) => a.duration_days - b.duration_days);
  if (filters.sort === "duration-desc") matches.sort((a, b) => b.duration_days - a.duration_days);
  return matches;
}
export function distanceKm(points: { latitude: number; longitude: number }[]) {
  let total = 0;
  for (let i = 1; i < points.length; i++) {
    const a = points[i - 1],
      b = points[i],
      r = Math.PI / 180,
      dlat = (b.latitude - a.latitude) * r,
      dlng = (b.longitude - a.longitude) * r,
      h =
        Math.sin(dlat / 2) ** 2 +
        Math.cos(a.latitude * r) * Math.cos(b.latitude * r) * Math.sin(dlng / 2) ** 2;
    total += 6371 * 2 * Math.atan2(Math.sqrt(h), Math.sqrt(Math.max(0, 1 - h)));
  }
  return Math.round(total);
}

  catalogue: Catalogue,

export function routeModel(c: Catalogue, tourId: string) {
  const stops = c.stops
    .filter((s) => s.tour_id === tourId)
    .sort((a, b) => a.sort_order - b.sort_order || a.id.localeCompare(b.id));
  const points = stops.map((s) => {
    const p = c.places.find((p) => p.id === s.place_id);
    return [p?.latitude ?? s.latitude, p?.longitude ?? s.longitude] as [number, number];
  });
  const parents = points.map((_, i) => i),
    root = (i: number): number => (parents[i] === i ? i : root(parents[i]));
  for (let i = 0; i < points.length; i++)
    for (let j = 0; j < i; j++) if (metres(points[i], points[j]) <= 75) parents[root(i)] = root(j);
  const groups = new Map<
    number,
    { key: string; position: [number, number]; numbers: number[]; stops: typeof stops }
  >();
  stops.forEach((s, i) => {
    const key = root(i),
      group = groups.get(key) ?? { key: s.id, position: points[key], numbers: [], stops: [] };
    group.numbers.push(i + 1);
    group.stops.push(s);
    groups.set(key, group);
  });
  const segments = points.slice(1).map((p, i) => ({
    key: stops[i + 1].id,
    points: [points[i], p],
    dayId: stops[i + 1].itinerary_day_id,
  }));
  return { stops, points, groups: [...groups.values()], segments };
}
function metres(a: [number, number], b: [number, number]) {
  const r = Math.PI / 180,
    dLat = (b[0] - a[0]) * r,
    dLng = (b[1] - a[1]) * r,
    v = Math.sin(dLat / 2) ** 2 + Math.cos(a[0] * r) * Math.cos(b[0] * r) * Math.sin(dLng / 2) ** 2;
  return 12742000 * Math.asin(Math.sqrt(Math.min(1, v)));
}
